\begin{center}{\large\bfseries Performance of the multi-RHS dielectric BIE solver}\\[2pt]
\small geometry, parallelism, and right-hand-side batching\end{center}

\noindent
FMM3D-accelerated dielectric BIE for monolayer graphene (slab $L{=}90$, $L_z{=}3.35$,
$\varepsilon_{\mathrm{in}}{=}3.5$). All timings are from exclusive Flatiron \texttt{genoa} nodes
(96 cores), one node per thread count, with \texttt{OMP\_NUM\_THREADS} \emph{and}
\texttt{OPENBLAS\_NUM\_THREADS} pinned. Data in \texttt{../data/}, figures in \texttt{../figs/}.
Throughput $\Theta=N\,\nd/t_{\mathrm{fmm}}$ (M source$\cdot$RHS evals/s); the FMM cost fits
$t_{\mathrm{fmm}}\approx a+b\,\nd$ ($a$ shared, $b$ per-density).

\section{Uniform vs.\ non-uniform distributions}
The same FMM kernel was run on the real slab interface and on a 3D-uniform cloud of equal $N$
(\texttt{fmm\_bench.csv}, \texttt{fmm\_bench\_uniform.csv}). The slab is \textbf{up to $7\times$
slower}: peak throughput $2.37$ (slab) vs $12.87$ (uniform). The penalty (Table~\ref{t:pen}) grows
with thread count and factors at $N{=}461\,376$ as
\[
\underbrace{7.03\times}_{\text{96 thr}}=\underbrace{2.75\times}_{\text{1 thr (extra work)}}\times
\underbrace{2.54\times}_{\text{scaling gap}},
\]
the scaling gap because the slab parallelizes $1\!\to\!96$ by only $20.4\times$ vs the uniform
$52.0\times$. Cause: FMM3D's cubic octree on a sheet occupying only $L_z/L\approx3.7\%$ of the box
wastes $\sim$5 levels on empty $z$-space (refining like a 2D quadtree, deeper) and clusters boxes
into a thin slab that load-balances poorly. (The uniform $N{=}93\,312$ entry is an anomalous
random-tree outlier, ratio $<1$.)

\section{Speedup from threads and \nd}
Threads and \nd{} are orthogonal levers on the FMM kernel (slab, $N{=}461\,376$, from
\texttt{fmm\_bench.csv}; see \texttt{../figs/fmm\_bench.png}, \texttt{fmm\_speedup.png}).
\emph{Batching \nd} amortizes a flat $\sim$3.7$\times$ that plateaus (per-RHS $t_{\mathrm{fmm}}/\nd$:
$19.10\to7.94\to5.47\to5.14$\,s for $\nd{=}1,4,16,36$ $\Rightarrow$ $1.0,2.4,3.5,\mathbf{3.7}\times$).
\emph{Threads} give $1\!\to\!96$ speedups of $17.9\times$ ($N{=}33$k) to $20.4\times$
($N{=}461$k), near-ideal to $\sim$16 threads then saturating---\textbf{96 threads $\approx$ 64}.
Combined (Table~\ref{t:comb}) they reach $\sim$73$\times$ at $\nd{=}36$/64 threads. These are
distinct: $\sim$3.7$\times$ (\nd), $\sim$18--20$\times$ (threads), $\sim$73$\times$ (both)---not to
be conflated.

\section{How multi-RHS accelerates the solve}
The neighbour pair densities $\rho_{ij}=\varphi_i\varphi_j$ are all RHS of the \emph{same} operator
$A=\tfrac12\gamma^{-1}+D^{\!\top}$, so they are solved by block GMRES with each matvec a single
$\nd{=}K$ batched FMM. Two levels:

\textbf{(i) FMM kernel.} A direct phase breakdown (\texttt{tools/nd\_timing.f90}, $N{=}200$k, 1 thr;
\texttt{fmm\_phase\_breakdown.csv}, Table~\ref{t:phase}) shows the shared cost is \emph{not} tree
construction ($\sim$2\%) but per-interaction geometry/operators---the M2L translation operators and
the $1/r$ near field---computed once and reused across all densities. Every FMM3D kernel does this
via an inner density loop, e.g.\ the near kernel \texttt{l3ddirectcg}:
\begin{lstlisting}
cd = inv4pi/sqrt(dd)      ! 1/r : expensive sqrt, ONCE per source-target pair
do idim = 1,nd            ! densities: only cheap multiply-adds
   pot(idim,i) = pot(idim,i) + cd*charge(idim,j) ; ...
enddo
\end{lstlisting}
So $\sim$84\% is shared and $\nd{=}36$ costs $6.8\times$ (not $36\times$) one call; the per-RHS
ceiling is $(a{+}b)/b\approx6\times$ (uniform), $\sim$4$\times$ for the slab's heavier near field.

\textbf{(ii) Block solve.} Instrumented (\texttt{solve\_breakdown.csv}): the FMM is \textbf{94--97\%}
of the solve, and block GMRES does \textbf{no} iteration saving (\texttt{iter}=\texttt{nmv}=7 for
$K{=}1$ and $K{=}36$ alike)---its only benefit is the batched FMM. Hence the per-RHS solve
amortization just \emph{tracks the FMM}: $61.4/15.3=\mathbf{4.0\times}$ (1 thr),
$11.6/2.54=4.6\times$ (16 thr). The $K$-sweep (Fig.~\ref{f:perrhs}) plateaus at this $\sim$4$\times$
floor (per-RHS $15.63\to3.62$\,s, $K{=}1\to36$), \emph{not} along $1/K$. (An earlier ``$18\times$''
was a thread-contamination artifact from unpinned threads; at 1 thread the $K{=}36$ FMM alone is
537\,s, so its reported 127\,s total was impossible.)

\noindent\textbf{Recommendations.} Run at 32--64 threads (96 buys nothing); always batch co-located
densities (free $\sim$4$\times$); the thin-slab geometry---not the kernel---is the dominant
remaining cost.
